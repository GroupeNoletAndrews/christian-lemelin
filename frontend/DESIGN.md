# Système de design — Entreprises Christian Lemelin

> **Source de vérité du design.** À consulter **avant de créer ou modifier toute UI**, et à **mettre à jour à chaque changement de design** (voir [Journal](#journal-des-modifications) en bas).
>
> Référence visuelle : template Framer **OPUS** — https://opus-template.framer.website/

---

## 1. Principes

Le langage visuel est **simple, épuré et aéré**, calqué sur OPUS :

- **Espace avant tout** — du whitespace généreux entre sections et autour du contenu. Laisser respirer.
- **Retenue** — peu d'éléments par écran, une hiérarchie claire, pas de décor superflu.
- **Un seul accent fort** — le bleu électrique, utilisé avec parcimonie (liens, CTA, détails). Le reste est neutre.
- **Hairlines, pas de boîtes lourdes** — séparateurs fins (`border-border`) plutôt que cartes contrastées.
- **Mouvement sobre** — animations discrètes, jamais gratuites ; toujours respecter `prefers-reduced-motion`.

## 2. Couleurs

Tokens définis dans [`src/app/globals.css`](src/app/globals.css) (`@theme inline`). **Toujours utiliser les classes Tailwind ci-dessous — jamais de hex en dur dans les composants.**

| Token | Valeur | Usage | Classe Tailwind |
|---|---|---|---|
| `background` | `#f3f3f1` | Fond de page (crème) | `bg-background` |
| `surface` / `surface-elevated` | `#ffffff` | Cartes, panneaux élevés | `bg-surface` |
| `foreground` | `#141414` | Texte principal (noir **neutre**, pas de vert) | `text-foreground` |
| `foreground-muted` | `rgba(20,20,20,.6)` | Texte secondaire / légendes | `text-foreground-muted` |
| `ink` | `#111111` | Fond des sections sombres (neutre) | `bg-ink` (texte `text-white`) |
| `accent` | `#0048f9` | Accent bleu — **uniquement** flèche de lien et fond de bouton | `bg-accent` |
| `accent-hover` | `#0039c4` | Survol de l'accent (dérivé) | `bg-accent-hover` |
| `border` | `rgba(151,151,151,.2)` | Séparateurs fins (hairlines) | `border-border` |

⚠️ **Pas de texte bleu.** Le bleu ne sert que pour : la flèche `↗` des liens et le fond des boutons (texte blanc dessus). Jamais pour du texte (titres, chiffres, codes…). Pas de teinte verte nulle part — les noirs sont neutres.

> 🏠 **Page d'accueil — aucun bleu (demande client).** Sur `/` **uniquement**, l'accent bleu est neutralisé en **noir** ; les pages internes gardent le bleu. Mécanisme dans [`globals.css`](src/app/globals.css) : `--color-accent`/`--color-accent-hover` sont sortis du bloc `@theme inline` vers un `@theme` **runtime** (les utilitaires compilent donc en `var(--color-accent)`), puis réassignés via **`body:has([data-home-neutral])`** → la valeur cascade dans le header, le footer et toutes les sections **sans toucher chaque composant**. Le marqueur `[data-home-neutral]` est rendu par [`SiteChrome`](src/components/layout/SiteChrome.tsx) seulement sur `/`. Les **sections sombres** (`data-header-theme="dark"`) repassent l'accent en **blanc** (sinon un accent noir disparaîtrait sur fond noir) ; un `bg-accent` devenu blanc y garde un **label foncé** (bouton « Nous joindre »). Focus-visible et `::selection` aussi neutralisés sur `/`.

> ⚠️ **Migration en cours :** certains composants utilisent encore `text-zinc-*`, `black/8`, `black/12`. À remplacer progressivement par les tokens ci-dessus.

## 3. Typographie

Chargées via `next/font/google` dans [`src/app/layout.tsx`](src/app/layout.tsx).

| Police | Rôle | Classe |
|---|---|---|
| **Onest** (variable) | Titres **et** corps de texte | `font-sans` / `font-display` (par défaut sur `body`) |
| **Fragment Mono** (400) | Labels, codes | `font-mono` |

**Conventions :**
- **Titres** : Onest, **casse normale** (pas de capitales), poids medium/semibold, grande taille, `leading` serré (`leading-[1.05]`). OPUS n'utilise pas de capitales condensées.
- **Labels** : Fragment Mono, petit, `uppercase`, `tracking` large (`tracking-[0.18em]`), en `text-foreground-muted`.
- **Corps** : Onest, poids normal, `leading-relaxed`, `text-foreground-muted` pour le secondaire.
- Tailles fluides via `clamp()` pour les grands titres.

> ⚠️ **Migration en cours :** les composants hérités utilisent `font-display` en `uppercase` (esthétique Bebas Neue). À convertir vers des titres Onest en casse normale lors des prochaines passes.

## 4. Espacement & layout

- **Padding de section** généreux : viser `py-24`/`py-32` desktop, `py-16`/`py-20` mobile.
- **Largeur de contenu** bornée (`max-w-*`) avec marges latérales confortables (`px-6` mobile, `px-14`+ desktop).
- Espacements verticaux à l'échelle Tailwind ; privilégier la respiration au remplissage.
- Grilles simples, alignées ; éviter la surcharge d'éléments.

## 5. Composants

**Primitives réutilisables** (dans [`src/components/ui/`](src/components/ui/)) — **à réutiliser, ne pas réinventer** :
- [`ArrowLink`](src/components/ui/ArrowLink.tsx) — lien bleu avec flèche `↗`.
- [`Marquee`](src/components/ui/marquee.tsx) — ruban défilant en boucle (pattern ui-layouts/magicui). Props `reverse`/`pauseOnHover`/`vertical`/`repeat` ; vitesse et espacement via les custom properties `--duration`/`--gap` (réglables par breakpoint). L'animation (`@keyframes marquee` + `--animate-marquee`) vit dans [`globals.css`](src/app/globals.css) et est **désactivée sous `prefers-reduced-motion`**. Helper `cn()` dans [`src/lib/utils.ts`](src/lib/utils.ts).
- [`linear-modal`](src/components/ui/linear-modal.tsx) — **dialogue morphant** (`Dialog`/`DialogTrigger`/`DialogContainer`/`DialogContent`/`DialogImage`/`DialogTitle`/`DialogDescription`/`DialogClose`, pattern ui-layouts/motion-primitives) : une carte-trigger se **déplie** (shared `layoutId` sur le conteneur, l'image et le titre) en un panneau **portalisé** (`createPortal`), avec **scroll-lock** (Lenis + `body`), **Escape**/clic-extérieur, gestion du focus. Fallback `prefers-reduced-motion` = simple fondu (pas de morph). Prop **`morph`** (défaut `true`) : `morph={false}` désactive le shared-element (le modal **fond/zoome** au lieu de redimensionner l'image du trigger — évite les déplacements parasites). Le voile sombre intégré (`bg-black/92` + `backdrop-blur`) est activable via la prop **`dim`** (défaut `true`) ; `dim={false}` seulement quand le contenu fournit son propre fond. Le modal matériaux utilise désormais ce voile par défaut (plus de shader derrière le modal). **`DialogContent` accepte un `style` de type `MotionStyle`** (pas seulement `CSSProperties`) → on peut lui passer des `MotionValue` de transform (ex. le `rotateX`/`rotateY` du tilt 3D du modal matériaux).
- [`ShaderBackdrop`](src/components/ui/ShaderBackdrop.tsx) — gradient animé **monochrome** (`@shadergradient/react`, WebGL) chargé en `dynamic`/`ssr:false`, derrière une **error boundary** qui retombe sur un dégradé CSS statique si le runtime WebGL échoue. Tons noir/gris/blanc **uniquement**. *(Actuellement non utilisé — disponible comme primitive.)*
- [`ContactFab`](src/components/ui/ContactFab.tsx) — **bouton « Contactez-nous »** flottant en bas à droite : pill **noir (`bg-foreground`), icône + label, non masquable** (pas de croix). Au **clic**, il déplie un panneau noir avec le message complet (« Un projet métal en tête ? » + délai 24 h) et un lien `/contact` ; clic-extérieur / Échap referment le panneau. Affiché sur **toutes les pages internes** (jamais sur `/` ni `/contact`) ; l'accueil garde la grande section `ContactCTA`. Apparaît après ~1 s (entrée spring, fallback reduced-motion). Rendu par [`SiteChrome`](src/components/layout/SiteChrome.tsx).

> **Pas de pilules/badges.** Ni eyebrow (pill point bleu + label en tête de section), ni tag (pill outline de catégorie/matériau). Les sections s'ouvrent directement sur leur titre ; les métadonnées s'écrivent en texte simple.

- **Boutons / CTA** : pill `rounded-full`, fond `bg-accent`, **texte blanc** (jamais texte sombre sur le bleu), survol `bg-accent-hover`. Variante secondaire : bordure `border-border` + texte `text-foreground`.
- **Cartes / panneaux** : `bg-surface`, séparation par `border-border` (hairline) plutôt qu'ombres marquées.
- **Focus** : contour bleu `#0048f9` (défini globalement via `:focus-visible`). Ne pas le retirer.

## 7. Layout & patterns OPUS *(observés sur le template — à reproduire)*

Captures de référence prises au 1440px. Le layout d'OPUS repose sur ces patterns — **toute nouvelle section doit s'en inspirer.**

- **Navigation** : barre **minimale** transparente (logo à gauche + un seul bouton pill « Menu » bleu à droite), repliée sur **tous** les écrans comme OPUS. Au clic → **overlay plein écran noir** (`bg-black`) : liens en très grand (Onest) à gauche, contact + bouton « Nous joindre » blanc à droite. La **barre flotte au-dessus de l'overlay** (`z-[96]`, sous le preloader/modal `z-100`) et le **même bouton** bascule **en place** en « Fermer » (pill blanc, texte foncé) : c'est l'**unique fermeture, pas de ✕ séparé** — donc toujours parfaitement aligné avec « Menu » (plus de décalage). L'overlay n'a plus sa propre rangée logo+✕ (le logo de la barre flottante, inversé blanc, sert aux deux états) ; le **cadre du menu est descendu sous la barre** (`pt-24` sur le wrapper) pour qu'aucune ligne (bordure du cadre / divider) ne chevauche le logo, sur mobile comme desktop. Sticky : fond `backdrop-blur` + hairline au scroll. **Auto-hide directionnel** : la barre **se cache (slide `translateY(-100%)`) au scroll vers le bas** (après ~120 px) et **réapparaît animée au scroll vers le haut** (`motion.header`, dead-zone de 6 px anti-jitter ; reste visible si le menu est ouvert).
  - **Animation d'ouverture/fermeture (façon pointlaz.com)** : révélation **graduelle ligne par ligne** — chaque lien **monte depuis un masque** (`overflow-hidden`) et un **trait se dessine** (`scaleX`) sous lui, en cascade (`custom={i}`, ~1,7 s). La **fermeture** rejoue l'inverse (liens redescendent dans le masque, traits se rétractent) puis l'overlay s'efface. Variants `overlayV`/`linkV`/`lineV`/`fadeV` dans [`Header.tsx`](src/components/layout/Header.tsx).
- **Liens** : texte **souligné** (couleur neutre `text-foreground` ou `text-white`), souligné fin `underline-offset`, + flèche **`↗` bleue**. Le texte n'est **jamais** bleu. Composant [`ArrowLink`](src/components/ui/ArrowLink.tsx).
- **Parallax images** : l'image est **légèrement** sur-dimensionnée (**115%**) et translate verticalement (`amount` ~5%) au scroll → parallax **discret** « les images me suivent » (volontairement peu de « zoom »). Composant [`ParallaxImage`](src/components/ui/ParallaxImage.tsx) (utilisé par À-propos & Installations via `SlotParallaxImage`) ; les cartes **Réalisations** ont leur propre parallax inline aux mêmes réglages. Les cartes **Solutions & Matériaux** utilisent un simple `object-cover` (1×, sans oversize). Respecte `prefers-reduced-motion`, fluide via Lenis.
- **Hero** : **bannière vidéo plein cadre** (`videoLemelin.mp4`, autoplay/muette/loop, sans contrôles) façon pointlaz, en style OPUS. Contenu ancré en bas à gauche, texte blanc sur dégradé de lisibilité : titre **immense** « Les Entreprises / Christian Lemelin » (Onest) sur **deux lignes décalées** façon OPUS (1re ligne tirée vers la gauche `md:-ml-9` — déborde un peu du padding ; 2e ligne décalée à droite `md:ml-16` ; lignes **espacées** `leading-[1.02]` + `mt-2` ; `md:whitespace-nowrap` ; empile naturellement sur mobile). **Wrapper pleine largeur, ancré à gauche** (pas de `mx-auto`/`max-w`) : le titre colle au **bord gauche de la vidéo**. En dessous, une rangée `md:grid-cols-[1fr_auto] justify` — l'**intro est alignée sous « Christian Lemelin »** (`md:ml-16`, même indent que la 2e ligne) et le **lien `↗` est poussé au bord droit** de la vidéo. Le texte **apparaît après 3 s** (révélation en cascade). `data-header-theme="dark"`. Voir [`Hero.tsx`](src/components/sections/Hero.tsx).
- **Sections** : pas d'eyebrow ni de pilule — chaque section **s'ouvre directement sur son titre**.
- **Sections alternées** : blanc `#fff` / crème `#f3f3f1` / **noir neutre `#111111`** (token `ink`, texte blanc — **pas de teinte verte**). Très grand padding vertical (respiration).
- **Titres** : Onest, **casse normale**, taille géante (`clamp`), `leading` serré. Jamais tout en majuscules.
- **Stats** ([`StatsBar.tsx`](src/components/sections/StatsBar.tsx)) : très grands chiffres en **`text-foreground` neutre** (pas de bleu) + petit label gris, **centrés**. Section **fond crème (`bg-background`, sans bordure)** pour **fusionner avec le reste** (plus de bande blanche). Les chiffres sont **animés en compteur** (count-up de 0 → cible) au scroll dans la vue (`useInView` + `animate` sur un `useMotionValue`, formatage FR « 2 400 », suffixes `+`/`%` préservés, `tabular-nums`, fallback `prefers-reduced-motion`). Délimité par des **hairlines qui se dessinent** (`scaleX` 0→1, même easing `[0.76,0,0.24,1]` que le menu). En bas, un **mur de logos clients** : **deux rangées de tuiles** (`Marquee` primitive, sens opposés, `pauseOnHover`) qui défilent en boucle, **pleine largeur** (full-bleed `w-screen`, bords fondus vers le crème). Chaque tuile affiche un **vrai logo** (fichiers dans [`public/logos/`](public/logos/) — entreprises québécoises réelles servant de placeholder, à remplacer par les vrais clients), **en niveaux de gris atténués au repos → pleine couleur + léger soulèvement au survol** (`group-hover:grayscale-0` + `-translate-y`), de sorte que les autres tuiles **restent visibles** (aucune inversion, aucun bleu). Logos en `<img>` (PNG/SVG). La grille de chiffres est volontairement **compacte** (la vedette est le mur de logos).
- **Liste de services (Savoir-faire)** : **bloc arrondi inséré** (`rounded-[1.75rem] md:rounded-[2.5rem] overflow-hidden`, `min-h-[calc(100svh-1.5rem)]`) sur fond de page **crème** : la section externe garde une **fine marge** (`p-3 md:p-4`) pour laisser **voir le fond clair autour** des coins arrondis. `data-header-theme="dark"` sur la section externe (évite le scintillement du header sur la marge crème). **La photo est le sujet, pas un fond** (revu le 2026-08-15) : elle vit dans un **panneau encadré** (`ring-1 ring-white/15`, `aspect-[4/3]` à tous les breakpoints — le portrait `4/5` sur desktop faisait de l'image le point haut de la page) en **colonne droite** sur desktop, avec **légende du savoir-faire actif**, **compteur `n / 4`** et **flèches haut/bas posées dessus** (`CaretUp`/`CaretDown`, cercles en verre) qui **naviguent le carousel** de façon cyclique. Auparavant l'image était plein cadre sous **trois voiles noirs** — la section lisait « noir minimaliste » mais on ne voyait plus ce qu'on fabrique. Le **crossfade façon Apple** (skiper-ui *Skiper76*) est conservé sur le panneau (entrée depuis la droite `x:+8%`/`scale 0.92` → repos, sortie vers la gauche ; overscan de repos ramené à `1.04`, l'image n'étant plus full-bleed). À gauche : le titre + des **pastilles-accordéon en verre** (`rounded-[1.6rem]`, icône `+` circulée ; la pastille **active** se **déplie** pour révéler la description). Grille `lg:grid-cols-[1.05fr_0.95fr]` à **placement explicite** (`col-start`/`row-start`/`row-span`) pour que l'ordre mobile soit **titre → photo → liste**. **Un seul lien** clôt la section, **hors des pastilles** (un `<a>` dans un `<button>` est invalide et volait le clic). Photos **en couleur** par défaut (la bascule monochrome reste dans l'admin). Voir [`SavoirFaire.tsx`](src/components/sections/SavoirFaire.tsx).
- **Mobilier hospitalier (accueil)** : section **claire** (`bg-background`, `data-header-theme="light"`, `py-24 md:py-32`) intercalée entre Savoir-faire (sombre) et Réalisations — l'alternance clair/sombre est préservée. Mise en page **éditoriale** : `lg:grid-cols-[1.15fr_0.85fr]` — titre + deux paragraphes + le lien de section à gauche, **photo principale `aspect-[4/5]`** (`rounded-2xl border border-border`) à droite ; puis **4 points sur hairlines** (`border-t` sur la grille, `border-b` par cellule, `lg:border-b-0`) et une **bande de 3 photos**. Les 4 photos sont des **emplacements éditables** (`mobilier-hospitalier` dans le registre). Pas d'eyebrow (§5). Voir [`MobilierHospitalier.tsx`](src/components/sections/MobilierHospitalier.tsx).
  - **Transition image (mesurée 1:1 sur le template via MCP Playwright)** : l'entrante surgit **de la droite** (`x:+8%`, `scale 0.92`, `opacity 0`) et **spring** vers l'état de repos (`scale 1.14` d'overscan, `x:0`) après un **décalage ~0,16 s** ; la sortante **glisse vers la gauche** (`x:-8%`, `scale 0.92`) et s'efface aussitôt → le « filmstrip » glisse vers la gauche, léger overshoot spring, très fluide. `AnimatePresence mode="sync"` + `motion/react`. - **Cartes process** (section sombre) : `rounded-2xl`, bordure subtile, titre ; la carte active est plus claire.

**Patterns « wow » des pages internes :**
- **`SolutionsTimeline`** ([`/solutions`](src/components/sections/SolutionsTimeline.tsx)) — **« stroke-follows-scroll » façon skiper-ui [skiper19](https://skiper-ui.com/v1/skiper19)** (le code skiper19 est la **source de vérité**). Une grande **ligne bleue** (le **tracé EXACT de skiper19** : nœud bouclé + longues ondulations ; `strokeWidth 20`) **se dessine au scroll**, posée en grand **à droite** (motif). La scène est **sticky plein écran** ; les **6 sections** (solutions) s'affichent **en fondu enchaîné EN FONCTION du scroll** (à gauche : « 0X / 06 » mono + titre + tagline + carte image + lien « Découvrir »). **Clic → modale** (image + intro + points clés du 1er bloc `list`/`feature` + lien contact). **Pas de personnage** (idée de bonhomme allumette abandonnée — inutile). **Le scrubbing (dessin de la ligne via `strokeDashoffset`, opacité/translation des sections) est appliqué IMPÉRATIVEMENT au DOM via refs dans `place()`** appelé par `useMotionValueEvent(scrollYProgress,…)` — **aucun composant `motion` lié à une MotionValue de scroll** : **framer-motion v12 lève sinon une erreur WAAPI** « offsets must be monotonically non-decreasing » au montage (`pathLength`/`useTransform` de scroll en `style`). Ça évite aussi tout re-render. ⚠️ **Le `<section>` sticky ne doit pas avoir `overflow-hidden`** (casse `position:sticky`) — c'est la scène interne `h-screen` qui clippe. ### Scrollbar custom (look Firefox, partout)

On veut un scrollbar **fin façon Firefox, identique sur tous les navigateurs**. Le scrollbar **natif** ne permet pas ça de façon fiable, d'où la solution **DOM custom**.

**⚠️ Pièges du scrollbar natif (à ne pas refaire) :**
- Dès qu'on pose `scrollbar-width` (standard) sur un élément, **Chrome ignore complètement `::-webkit-scrollbar`** → impossible de combiner les deux pour styler.
- `html::-webkit-scrollbar` ne masque **pas** fiablement la barre racine de Chrome → il faut le sélecteur **`::-webkit-scrollbar` non préfixé (global)**.
- Le rendu natif varie selon la version de Chrome / l'OS → jamais cohérent.

**Solution retenue** (dans [`globals.css`](src/app/globals.css)) — masquer le natif :
```css
html, body { scrollbar-width: none; -ms-overflow-style: none; } /* Firefox / vieux Edge */
::-webkit-scrollbar { display: none; width: 0; height: 0; }     /* Chrome / Edge / Safari */
```
…puis le remplacer par un **élément DOM** : [`CustomScrollbar.tsx`](src/components/ui/CustomScrollbar.tsx).
- Barre fixe à droite, pouce **3px**, gris neutre `rgba(130,130,130,.5)` (lisible sur fond clair **et** sombre), arrondi.
- **Piloté par Lenis** (`useLenis()` → `scroll`/`limit`) avec fallback `window.scroll` ; recalculé sur `resize` + `ResizeObserver(body)`.
- **S'épaissit à ~7px + plus opaque au survol** (`group-hover`). `z-[90]`, desktop uniquement (`md:block`), masqué s'il n'y a pas de débordement.
- **Interactif** (comme un vrai scrollbar) : le pouce est **glissable** (`pointerdown`/`move`/`up` + `setPointerCapture`, mappe la position curseur → `lenis.scrollTo(y,{immediate,force})`) et la piste est **cliquable** (jump : centre le pouce sur le point cliqué). `touch-none select-none`, `cursor-grab`/`grabbing`.
- Comme c'est notre propre DOM, il s'affiche **à l'identique partout** — aucune dépendance aux quirks navigateur.
